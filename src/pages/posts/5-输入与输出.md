## 分享

- [OpenHanako — a personal AI agent with memory and soul](https://openhanako.com/) ：审美和思路非常到位，令我眼前突然一新的 Agent 产品 视频做的也是非常棒，质量很高
  开发者并非程序员背景，本人说是写作出身，年初也才开始 Vibe，从完成度以及视频内容来看，对软件以及 AI 的理解程度已经非常强了，恐怖的学习速度，能在短期内构建出这样一个完成的 Agent 产品，值得钦佩

我实际也体验了一下这个软件，做的蛮好的，但大概率是因为 Windows 原因，在某些样式的细节上，无法令我满意，整体还是很不错的。

当然，不得不令我思考的是，当下这些涌出的 AI agent 客户端/产品，在前端的配置上，都面临重复而冗杂的问题——

简单来说就是，每一个客户端，基本都是标配的那几大件，模型提供商，Skill，MCP，渠道/网关接入，记忆，plugins/hooks，以及最近又比较火的 Computer use，App screenshot，Agent 群聊 ......

虽然很多内容是可以直接继承的，例如 Skills 使用的目录（.agents/），以及 Openai 的 Auth 接入，CC 的 SDK 接入

但是在初次使用时，仍然需要花费一定的时间去配置。同时，这些客户端产品目前的更新迭代速度也是非常快，很容易出现一种，让人难以安心的去使用，去沉淀的感觉。很多的热门爆款产品，对我而言往往只是下下来看一眼，很难去长期使用，往往没过多久就会更新很多。（不过也看需求吧，可能确实没戳到我）

更不用说某些，宣传很牛逼，下下来一看拉了一坨大的 的 产品，点名某个推上的 “DeepSeek-gui”，（或许不止一个）我下的那个，官网丑的一批，实际使用的体验也是让我摸不着头脑，现在都是在抄 Codex 的布局了的说。

工程师们，我认为现在尤其需要提高的是 Taste，审美，（倒也不是说前端，是整个产品的设计理念，思想，以及风格，串起来的整体 Taste，当然前端也占很大一部分了）代码现在谁都能写，造重复轮子的成本也非常低，能不能吸引到人 ，还是看能不能抓住痛点，以及整体的 Taste，能不能戳到用户

或许从前，一个独立开发者，往往需要在代码落地上花费大量的时间，而无暇考虑其他。但现在，代码开发的速度已经飞起，就能说一个好的产品产出的速度就会更快吗？不能，因为节省的时间，需要拿去考虑其他的内容。如何讲故事？（bushi）如何宣传运营？如何维护？都是需要花费很多精力的（近期维护 DC-BLE，有时也容易气笑，某些用户的反馈的确蛮难绷的）

## 思考

这两天出现一种，一直想着干点什么来产出，但是实际有没什么可推进的东西
想了想不如主动的输入一些内容沉淀，而不是一味的想着输出，比如逛逛别人的博客，周刊，读读书，好好复习什么的，这样才能更好的输出

中间几天虽然一直也待在图书馆，但是好像一点动力都没有了，完全处于一直颓废的状态，毫无输入毫无输出。

## 复习

复习互换性和测量技术时，到后面直接进入一种模式
即基于我的所有课件内容，让 Codex 按章总结出 md 笔记，并出例题和测验，这样快速过一遍的效率高很多

**为什么不直接看课件？**
课件，我说实话做的太烂了，无论是条理性还是排版审美，都一坨。
从日期上看大多数都是使用的 6 年前的教材，也没啥更新，反正很难看的进去，让 AI md 梳理一遍，更有条理性，也方便随时提问写题，主打一个顺畅感
